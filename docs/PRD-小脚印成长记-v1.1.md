## 二、背景与目标

### 2.1 背景

现有 App 已具备「记录 → 展示 → 双机同步」的最小闭环（v1.0.0）。但存在三个结构性问题：

1. **模型限制**：`BabyInfo.fixedId = 1`，`getBabyInfo()` 固定 `limit 1`，物理上只能存一个宝宝。若二胎出生后再改，需要编写数据迁移脚本并回刷两台设备，成本远高于现在。
2. **模型错误**：`baby_info.device_role` 存的是「本机是爸爸还是妈妈」，这是**设备属性**而非宝宝属性。多宝宝后一台设备的身份不会随宝宝变化，该字段放错表。
3. **闭环缺口**：记录只能新增与删除，不能编辑；视频不参与同步；「清除缓存」为假实现；1000 条记录时时间轴会发起 1001 次查询。

### 2.2 要解决的问题

| 编号 | 问题 | 现状证据 |
|---|---|---|
| P-01 | 只能记录一个宝宝 | `models/baby_info.dart:3` `static const int fixedId = 1` |
| P-02 | 记录写错无法修改，只能删除重录 | `pages/record_detail_page.dart` 仅有 `_delete()` |
| P-03 | 找不到历史记录 | 无搜索入口，仅「全部/照片/录音/视频」四档筛选 |
| P-04 | 里程碑与日常琐事混在同一列表，重要时刻被淹没 | `growth_record` 无类型字段 |
| P-05 | 视频只存本机，换机即丢 | `pages/add_record_page.dart:521` 注释「MVP 视频仅保存在本机，不跨机同步」 |
| P-06 | 「清除缓存」不生效 | `pages/settings_page.dart:87` 注释「MVP 简化：暂只提示」 |
| P-07 | 用户不知道多久没备份，数据单点风险 | 无备份时间记录与提醒 |
| P-08 | 时间轴性能随记录增长线性劣化 | `pages/timeline_page.dart:41-43` 循环内逐条查 `media_item` |

### 2.3 成功指标

| 指标 | 口径 | 目标值 | 说明 |
|---|---|---|---|
| M-01 记录连续性 | 连续有记录的周数 ÷ 建档以来周数 | ≥ 70% | 手动统计，每季度看一次 |
| M-02 月记录量 | 自然月内新增 `growth_record` 条数 | ≥ 12 条/月 | 约每周 3 条 |
| M-03 备份新鲜度 | 当前日期 − 最近一次成功备份日期 | ≤ 30 天 | App 内可直接读取 |
| M-04 时间轴首屏耗时 | 1000 条记录时从进入 Tab 到列表可见 | ≤ 800 ms | 中端安卓机实测 |
| M-05 双机数据一致率 | 同步后两机 `growth_record` 条数与内容 MD5 一致 | 100% | 同步完成页展示对比结果 |

> M-01/M-02 为人工观察指标，不设埋点（本产品无网络上报）。

## 三、名词与术语

| 术语 | 定义 |
|---|---|
| 记录（Record） | `growth_record` 一行，代表一个时间点发生的事，含文字、标签、媒体 |
| 记录类型（record_type） | `diary` 日常 / `milestone` 里程碑 / `metric` 测量 / `vaccine` 疫苗 |

| 幂等键 | 同步中用于防重复写入的 `uuid` + `last_modify_ts` |
| 长图 | 由若干条记录渲染成的单张 PNG，用于微信/相册分享 |
| 备份包 | `BackupService.exportBackupZip()` 产出的 ZIP，含 DB 与 compressed 目录 |

| 广告、内购 | 与产品定位冲突 |
| iOS 版本 | 本期仅安卓 |
| 成长曲线对比 WHO 百分位 | 属 v1.3，需引入标准数据表 |
| PDF 打印版成长册 | 属 v1.2，长图验证后再做 |

## 五、方案对比与选型

### 5.1 多宝宝的数据组织方式

| 方案 | 实现成本 | 复杂度 | 风险 | 综合评价 |
|---|---|---|---|---|
| A. 单库加 `baby_id` 外键（推荐） | 低 | 低 | 低：一次迁移，同步协议加一个字段 | **采纳**。查询加 `where baby_id = ?` 即可，备份仍是单文件 |
| B. 每宝宝独立数据库文件 | 中 | 高 | 中：同步需多文件协商，备份需打包多库 | 不采纳，复杂度不值得 |
| C. 不改模型，二胎新建 App 分身 | 低 | 低 | 高：两台设备各存一份，同步彻底失效 | 不采纳 |

### 5.2 视频同步策略

| 方案 | 成本 | 体验 | 风险 | 综合评价 |
|---|---|---|---|---|
| A. 压缩后全量同步（推荐） | 中 | 好：换机不丢 | 中：单文件可能过大 | **采纳**，并加 50 MB 单文件阈值 |
| B. 仅同步封面 + 元数据 | 低 | 差：另一台点开是空 | 低 | 不采纳，等于没解决 |
| C. 不同步，仅提示手动拷贝 | 极低 | 差 | 中：用户不会做 | 不采纳 |

> 方案 A 的阈值规则：压缩后 ≤ 50 MB 自动同步；> 50 MB 在记录详情标「大文件未同步」并提供单条手动同步入口。

### 5.3 分享形态

| 方案 | 成本 | 体验 | 综合评价 |
|---|---|---|---|
| A. 单条记录长图（RepaintBoundary → PNG） | 低 | 直接发微信 | **采纳（本期）** |
| B. 月度 / 年度回顾长图 | 中 | 更有仪式感 | v1.2 |
| C. PDF 成长册 | 高 | 可打印 | v1.3 |

### 5.4 演进路径

| 阶段 | 内容 | 进入下一阶段的触发条件 |

| 本期 v1.1 | 模型修正 + 闭环补齐 + 里程碑 + 分享 + 提醒 + 隐私锁 | 连续使用 4 周且月记录量 ≥ 12 条 |

### 6.3 核心场景（主流程 / 分支 / 异常）

**场景 S1：快速记录一个里程碑**

1. 打开 App（已解锁）→ 时间轴 Tab
2. 点 FAB → 新增记录页
3. 选类型「里程碑」→ 从预置库选「第一次独立行走」（自动带出建议月龄 9–17 月）
4. 拍照 1 张 → 保存
5. 返回时间轴，该条带里程碑徽标，且出现在「里程碑」Tab 的对应分类下

- 分支：库里没有想要的 → 选「自定义里程碑」，手填名称与分类
- 异常：拍照权限被拒 → 提示「去设置开启相册权限」，文字记录仍可保存

**场景 S2：双机同步**

1. 妈妈机「我的 → 双机同步」→ 开启接收（显示本机 IP）
2. 爸爸机输入 IP → 连接 → 显示进度（记录 / 媒体 / 冲突数）
3. 完成后展示「新增 N，更新 M，冲突 K」，并写入 `sync_log`

- 分支：IP 变了 → 手动输入；本期不做二维码（v1.2）
- 异常：同一秒两端都改了同一条 → 按 `last_modify_ts` 取新，相等则保留内容较长的，冲突数 +1 并记录

**场景 S3：换机恢复**

1. 新机安装 App → 引导页选「从备份恢复」
2. 选择 ZIP → 校验 `manifest.json` 版本 → 还原 DB 与媒体
3. 完成后进入时间轴

- 异常：ZIP 版本高于当前 App → 提示先升级 App，拒绝导入以免模型错乱

### 7.1 数据模型与多宝宝（FR-1xx）

#### FR-101 数据结构升级至 v2【必须】

**规则**
- `_dbVersion` 由 1 升至 2，新增 `onUpgrade` 分支
- 迁移前必须把 `little_footprint.db` 复制为 `little_footprint.db.bak.v1`，迁移成功保留 7 天，失败则回滚
- 迁移必须幂等：以 `PRAGMA user_version` 为准，重复执行不产生副作用
- `baby_info` 因主键需变更（固定 1 → 自增），必须**重建表**（SQLite 不支持改主键）

**参考 DDL**

```sql
-- 1) 配置表：承接设备级配置（device_role 迁出）
CREATE TABLE app_setting (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL DEFAULT ''
);

-- 2) 重建 baby_info
CREATE TABLE baby_info_v2 (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  baby_name      TEXT    NOT NULL DEFAULT '',
  birth_date     TEXT    NOT NULL,
  avatar_path    TEXT    NOT NULL DEFAULT '',
  gender         INTEGER NOT NULL DEFAULT 0,   -- 0 未知 / 1 男 / 2 女
  is_active      INTEGER NOT NULL DEFAULT 1,   -- 当前展示的宝宝
  last_modify_ts INTEGER NOT NULL DEFAULT 0
);
INSERT INTO baby_info_v2 (id, baby_name, birth_date)
  SELECT id, baby_name, birth_date FROM baby_info;
DROP TABLE baby_info;
ALTER TABLE baby_info_v2 RENAME TO baby_info;

-- 3) device_role 迁到配置表
INSERT INTO app_setting(key, value)
  SELECT 'device_role', device_role FROM baby_info_v2 LIMIT 1;
INSERT OR IGNORE INTO app_setting(key, value) VALUES ('device_role', 'husband');

-- 4) 记录与测量加 baby_id 及新字段
ALTER TABLE growth_record ADD COLUMN baby_id        INTEGER NOT NULL DEFAULT 1;
ALTER TABLE growth_record ADD COLUMN record_type    TEXT    NOT NULL DEFAULT 'diary';
ALTER TABLE growth_record ADD COLUMN milestone_code TEXT    NOT NULL DEFAULT '';
ALTER TABLE growth_record ADD COLUMN is_favorite    INTEGER NOT NULL DEFAULT 0;
ALTER TABLE growth_metric ADD COLUMN baby_id        INTEGER NOT NULL DEFAULT 1;

-- 5) 里程碑库
CREATE TABLE milestone_def (
  code            TEXT PRIMARY KEY,
  category        TEXT    NOT NULL,          -- motor_gross/motor_fine/language/social/cognition
  name            TEXT    NOT NULL,
  month_min       INTEGER NOT NULL DEFAULT 0,
  month_max       INTEGER NOT NULL DEFAULT 36,
  is_preset       INTEGER NOT NULL DEFAULT 1,
  sort_order      INTEGER NOT NULL DEFAULT 0
);

-- 6) 提醒
CREATE TABLE reminder (
  uuid           TEXT PRIMARY KEY,
  baby_id        INTEGER NOT NULL,
  kind           TEXT    NOT NULL,          -- vaccine/checkup/birthday/backup
  title          TEXT    NOT NULL,
  due_date       TEXT    NOT NULL,
  repeat_yearly  INTEGER NOT NULL DEFAULT 0,
  enabled        INTEGER NOT NULL DEFAULT 1,
  last_modify_ts INTEGER NOT NULL DEFAULT 0,
  is_deleted     INTEGER NOT NULL DEFAULT 0
);

-- 7) 索引（支撑时间轴与搜索）
CREATE INDEX idx_record_baby_time ON growth_record(baby_id, is_deleted, record_time DESC);
CREATE INDEX idx_record_type      ON growth_record(record_type);
CREATE INDEX idx_metric_baby_time ON growth_metric(baby_id, is_deleted, metric_time);
```

**验收**
- Given 旧版 DB 存在 1 个宝宝与 N 条记录，When 首次启动 v1.1，Then 宝宝、记录、媒体全部保留，`baby_id` 均为 1，且生成 `little_footprint.db.bak.v1`
- Given 迁移已完成，When 再次触发 `onUpgrade`，Then 不报错、数据条数不变
- Given 迁移过程抛异常，When 重启 App，Then 从 `.bak.v1` 还原并提示「数据升级失败已回滚」

#### FR-102 宝宝管理与切换【必须】

- `我的 → 宝宝管理`：列表展示全部宝宝（头像、小名、出生天数、当前标记）
- 支持新增 / 编辑 / 删除，上限 6 个
- 删除宝宝：`必须`二次确认并提示「该宝宝下 N 条记录与 M 个媒体将一并删除」；若只剩 1 个宝宝则隐藏删除入口
- 时间轴 AppBar 标题可点击，弹出宝宝切换器；切换后时间轴与档案同步刷新
- 当前宝宝存 `baby_info.is_active`

**验收**
- Given 已有 2 个宝宝，When 在时间轴切换到大宝，Then 列表只显示大宝记录且 AppBar 显示大宝名字与月龄
- Given 只有 1 个宝宝，When 进入宝宝管理，Then 无「删除」入口

#### FR-103 本机身份改造【必须】

- `device_role` 从 `baby_info` 迁移至 `app_setting`，取值改为 `owner` / `partner`，展示文案为「妈妈 / 爸爸」可自定义
- 兼容性：读到旧值 `husband`/`wife` 时映射为 `owner`/`partner`，`禁止`因此丢失已记录数据的归属

**验收**
- Given 旧数据中 `createDevice = 'wife'`，When 迁移后查看记录详情，Then 仍显示「记录人：妈妈」

### 7.3 里程碑（FR-3xx）

#### FR-301 预置里程碑库【必须】

- 首次启动写入 ≥ 40 条预置里程碑，覆盖五类：大运动、精细动作、语言、社交、认知
- 每条含建议月龄区间，用于「按月龄推荐」
- 代表条目：抬头、翻身、独坐、爬行、扶站、独立行走、叫人（爸妈）、说单词、说短句、自己用勺、自己穿衣、认人、怕生、挥手再见

**验收**
- Given 全新安装，When 进入里程碑 Tab，Then 可见按分类分组的至少 40 条待达成项
- Given 宝宝 7 个月大，When 查看「本月可关注」，Then 推荐条目的月龄区间包含 7

#### FR-302 记录里程碑【必须】

- 新增记录页增加「类型」选择：日常 / 里程碑
- 选「里程碑」时必须从库中选一条（或新增自定义里程碑），并写入 `milestone_code`
- 保存后生成 `growth_record`，`record_type = 'milestone'`
- 同一 `milestone_code` 对一个宝宝只允许达成一次；重复达成提示「已达成于 X 年 X 月 X 日」并阻止保存

**验收**
- Given 宝宝已记录「第一次翻身」，When 再次选择同一里程碑保存，Then 提示已达成日期且不写入新记录

## 九、业务流程与状态流转

### 9.1 记录生命周期

```
草稿(未入库)
  └ 保存 → 正常(is_deleted=0)
        ├ 编辑 → 正常(last_modify_ts 更新)
        ├ 收藏 → 正常(is_favorite=1)
        └ 删除 → 软删除(is_deleted=1)
                    ├ 同步传播 → 对端亦为软删除
                    └ 清理孤儿 → 媒体文件物理删除
```

状态迁移表：

| 当前状态 | 触发事件 | 条件 | 目标状态 | 允许操作 |
|---|---|---|---|---|
| 正常 | 编辑保存 | 有改动 | 正常 | 查看/编辑/删除/收藏/分享 |
| 正常 | 删除 | 用户二次确认 | 软删除 | 仅同步可读 |
| 软删除 | 同步接收删除标记 | — | 软删除 | 不可见 |
| 软删除 | 清理孤儿文件 | 无引用 | 物理删除 | — |

### 9.2 里程碑状态

| 状态 | 含义 | 进入条件 | 可执行 |
|---|---|---|---|
| 待达成 | 库中存在、未记录 | 默认 | 点击后预填新增记录 |
| 已达成 | 存在 `milestone_code` 匹配的记录 | 保存里程碑记录 | 查看详情、不可重复达成 |

### 9.3 同步状态机

```
空闲 → 等待连接 → 握手(交换版本/宝宝数) → 交换changeset → 传输媒体
     → 完成(写入sync_log) 
     ↘ 失败(超时/断网) → 可重试(保留已完成批次)
```

冲突裁决规则（`必须`按序执行，结果记入 `conflicts`）：

1. `last_modify_ts` 大者胜
2. 相等时，`content` 长度大者胜
3. 仍相等时，保留本机版本

## 十一、权限与安全

### 11.1 系统权限

| 权限 | 用途 | 申请时机 | 被拒后表现 |
|---|---|---|---|
| 相册/存储 | 选图、选视频、导出备份 | 首次点击对应功能时 | 提示去设置开启，文字记录不受影响 |
| 麦克风 | 录音 | 首次点击录音 | 提示，其他功能正常 |
| 通知 | 疫苗/体检/生日/备份提醒 | 首次开启提醒 | 提示手动开启，功能降级为「进入 App 查看」 |
| 相机（可选） | 直接拍照 | 首次点击拍照 | 回退为「从相册选择」 |

`禁止`在启动时一次性申请全部权限。

### 11.2 数据权限模型

本产品为单机双设备，无多用户体系。访问控制仅一档：

| 场景 | 控制方式 |
|---|---|
| 打开 App | 隐私锁（PIN / 生物识别），可关闭 |
| 分享长图 | 用户主动操作，内容自带水印，不含身份证/住址等字段 |
| 备份包 | 存放于 Download，提示「建议拷贝至电脑或移动硬盘」 |

### 11.3 合规要点（儿童个人信息）

- 本产品采集不满十四周岁未成年人信息（姓名、生日、照片、声音），属《个人信息保护法》下的**敏感个人信息**
- 当前架构为纯本地处理，不构成「向第三方提供」，是该产品的核心合规优势，`禁止`为便利性引入云端上传
- 数据结构中`禁止`新增身份证号、住址、学校等非必要字段（最小必要原则）
- 备份包为用户主动导出的本地文件，App 内`必须`提示保管责任

## 十二、异常处理清单

| 编号 | 场景 | 期望行为 | 禁止行为 |
|---|---|---|---|
| EX-01 | 相册/相机权限被拒 | 提示 + 跳设置入口，文字仍可保存 | 直接崩溃或静默失败 |
| EX-02 | 存储空间不足 | 保存前校验剩余空间，提示「需 X MB」 | 写半截文件留脏数据 |
| EX-03 | DB 迁移失败 | 从 `.bak.v1` 回滚并提示 | 直接覆盖用户数据 |
| EX-04 | 同步中拔网 | 保留已完成批次，提示可续传 | 回滚已同步内容 |
| EX-05 | 同步端口被占用 | 明确错误码 + 处理建议 | 只显示「同步失败」 |
| EX-06 | 同一里程碑重复记录 | 提示已达成日期，阻止保存 | 静默产生重复记录 |
| EX-07 | 导入版本不兼容的备份 | 拒绝并提示先升级 | 强行导入导致模型错乱 |
| EX-08 | 媒体文件丢失（被外部删除） | 详情页显示占位「文件已丢失」+ 记录仍在 | 整个页面报错 |
| EX-09 | 提醒权限被拒 | 降级为进入 App 时列表提醒 | 反复弹窗骚扰 |
| EX-10 | PIN 连续错误 | 锁定 60 s | 清空数据 |
| EX-11 | 删除最后一个宝宝 | 隐藏删除入口 | 允许删空导致 App 不可用 |
| EX-12 | 超长文本（>5000 字） | 正文可滚动，列表页截断 + 「…」 | 布局溢出 |
| EX-13 | 单条媒体 >100 MB | 拒绝保存并提示 | 写入后拖垮同步 |
| EX-14 | 时间为未来（补录误设） | 允许保存但列表标注「未来时间」 | 静默接受造成时间轴错乱 |
